Overview/Client

The c3po client

c3po is the only part of n-droids most people touch. It is a small Python library that turns a robot station into a Robot object with a blocking reset() / step() loop — no configuration files, no driver installs, no ROS.

Install

c3po needs Python 3.10 or newer. Its entire runtime dependency set is numpy, Pillow and websocket-client.

shell
git clone https://github.com/kaolab-research/c3po.git
cd c3po
pip install -e .
i

c3po is not on PyPI yet — the name there belongs to an unrelated project. Install from the repository, or vendor it into your own project with uv add --editable ./c3po.

Quick start

Plug the Ethernet cable into the station, then connect. The constructor opens the socket, performs the describe handshake and returns a ready object — or raises RobotNotFoundError if the station isn't reachable.

policy_loop.py
from c3po import Robot

with Robot(host="10.42.0.1") as robot:
    print(robot.station_model, robot.arms, robot.cameras)

    obs = robot.reset()
    while True:
        action = policy(obs)     # your code: dict of numpy arrays
        obs = robot.step(action)

That is the whole interface. Everything below is detail on the three verbs — connect, step, record.

Connecting

python
Robot(
    host="10.42.0.1",   # station address on the point-to-point link
    port=9090,          # WebSocket control port
    rate=50.0,          # requested control rate in Hz
)

rate is a request. The station caps it at what the hardware can sustain and reports the truth back through robot.spec(). On a DROID station it is pinned to 15 Hz.

Ask the station what it has

Every property below is derived from the manifest the station sends on connect. Nothing is hard-coded in your script, so the same file runs against a single arm or a bimanual rig.

python
with Robot() as robot:
    print(robot.station_model)   # "so101_teleop"
    print(robot.control_rate)    # 50.0
    print(robot.arms)            # ["follower"]
    print(robot.cameras)         # ["front_rgb", "wrist_rgb"]
    print(robot.controllers)     # ["leader"]
    print(robot.action_keys)     # ["follower/joint_position"]
    print(robot.joint_names)     # {"follower": ["shoulder_pan", "shoulder_lift", ...]}
✓

Write station-agnostic code. Read robot.action_keys and robot.controllers instead of hard-coding key names. A script written this way moves from a SO-101 to a bimanual ReBot without edits.

The loop

Call What it does
reset() Signals a new episode and returns the first observation. Blocks until every expected key has data — joint state, every camera, every controller.
step(action) Sends the action, then blocks until the next observation arrives and returns it.
step(None) Read-only step: wait for the next observation without commanding anything.
close() Disconnect. Called for you when the with block exits.

The station owns the cadence. If your policy takes 3 ms and the station runs at 50 Hz, step() blocks for the remaining 17 ms — so your loop is paced correctly without any timing code. A slow policy does not double-wait; it simply runs at the speed it can.

!

step() is synchronous. There is no async variant. If you need inference off the critical path, run the loop in a worker thread or keep your policy fast — a slow policy directly slows the robot.

Observations and actions

Both are flat dictionaries of NumPy arrays. Keys are namespaced by the device they come from.

observation
{
    "follower/joint_position": np.ndarray,  # (6,)   float64, radians
    "follower/joint_velocity": np.ndarray,  # (6,)   float64, rad/s
    "leader/joint_position":   np.ndarray,  # (6,)   float64, radians
    "front_rgb":               np.ndarray,  # (480, 640, 3)  uint8
    "wrist_rgb":               np.ndarray,  # (480, 640, 3)  uint8
}
action
{"follower/joint_position": np.ndarray}  # shape (6,), matching robot.action_keys

Key conventions

Pattern Meaning
{arm}/joint_position Joint angles in radians.
{arm}/joint_velocity Joint velocities in rad/s.
{controller}/joint_position A teleop device's reading — a leader arm, a gamepad.
{camera} An image. Depth streams arrive as uint16 millimetres.
✓

Teleop is a dictionary lookup. Because leader arms are just another key in the observation, leader-follower teleoperation is one line: robot.step({"{arm}/joint_position": obs["{leader}/joint_position"]}).

Collecting demonstrations

Recording happens on the station. Your loop does not change; you just wrap it in robot.recording(...).

collect.py
from c3po import Robot

with Robot(host="10.42.0.1") as robot:
    robot.on_status = lambda event, msg, data: print(f"[r2d2] {event}: {msg}")

    with robot.recording("session_001") as rec:
        while not rec.stop:
            obs = robot.reset()                  # new episode
            while not rec.stop and not rec.done:
                robot.step({
                    "follower/joint_position": obs["leader/joint_position"],
                })
            if rec.rerecord:
                robot.cancel_episode()           # throw this episode away
            rec.clear()                          # reset the flags

Keyboard controls

While a recording is active, c3po listens on the terminal for the same three keys LeRobot uses — no extra dependencies, and the same muscle memory.

Key Flag Effect
n rec.done Finish this episode and start the next one.
r rec.rerecord Discard the current episode and redo it.
q rec.stop Stop recording, finalize and close the dataset.

On Windows the listener degrades to a no-op; use Ctrl+C to stop and the context manager still finalizes the dataset cleanly.

Task-aware episode ends

Keyboard control and programmatic termination coexist. reward and done are stored with the frame as dataset metadata — they do not affect the control loop.

python
for _ in range(max_steps):
    if task_complete(obs):
        robot.step(policy(obs), reward=1.0, done=True)
        break
    obs = robot.step(policy(obs), reward=0.0)

Getting the data back

A finished dataset is served over HTTP on port 9091. Pull the whole tree — parquet, metadata and video — across the same cable, then clear it off the station.

python
with Robot(host="10.42.0.1") as robot:
    with robot.recording("session_001") as rec:
        ...                                   # collect episodes

    # Wait for the station to finish writing, then fetch it.
    robot.wait_for_status("dataset_ready", timeout=120.0)
    path = robot.download_dataset("session_001", dest="~/datasets")

    # The station is control-only storage — reclaim the space.
    robot.delete_dataset("session_001")

Runtime introspection

Two ways to see what the station is actually doing: ask for a snapshot, or subscribe to events.

python
print(robot.spec())   # effective control rate, camera FPS, recording state

robot.on_status = lambda event, message, data: handle(event, data)

Status events the station pushes:

  • recording_started
  • episode_finalized
  • episode_discarded
  • dataset_ready
  • watchdog_triggered
  • action_rejected
  • camera_error
  • cycle_overrun
  • arm_reset_complete
  • dataset_deleted

Reference

Robot methods

Method Description
reset() Start an episode; return the first full observation.
step(action=None, *, reward=0.0, done=False) Send an action and return the next observation.
close() Disconnect and release resources.
recording(name) Context manager for a dataset; returns a Recording.
start_recording(name) Begin a dataset without the context manager.
stop_recording() Finalize and close the dataset.
cancel_episode() Discard the in-progress episode.
wait_for_status(event, timeout=60.0) Block until a named status event arrives.
download_dataset(name, dest=".") Fetch a finished dataset over HTTP; returns the local path.
delete_dataset(name) Remove a dataset from the station.
spec() Live metrics snapshot from the station.

Robot properties

Property Type Description
station_modelstrStation identifier, e.g. "so101_teleop".
control_ratefloatThe station's native rate in Hz.
armslist[str]Arm names.
cameraslist[str]Camera keys in observations.
controllerslist[str]Teleop device keys in observations.
action_keyslist[str]Keys step() expects.
joint_namesdictArm key → ordered joint name list.
on_statuscallableSetter for the status callback.
camera_stream_infodictCapture and stream resolutions per camera.
controller_capabilitiesdictWhat each controller supports.
leader_home_positiondictEach leader's home pose, if known.

Recording object

Member Description
stopTrue once q was pressed.
doneTrue once n was pressed.
rerecordTrue once r was pressed.
episode_countEpisodes kept so far.
clear()Reset done and rerecord; advance the counter.

Exceptions

Exception Raised when
RobotNotFoundError The station isn't reachable, or the handshake failed.
RobotDisconnectedError The connection dropped, or an observation wait timed out.
IncompatibleVersionError The station reports an API major version c3po doesn't support.
ValueError An action dict is missing a required key.

Worked examples

Leader-follower teleoperation

teleop.py
from c3po import Robot

with Robot(host="10.42.0.1") as robot:
    arm = robot.arms[0]
    leader = robot.controllers[0]

    obs = robot.reset()
    while True:
        obs = robot.step({f"{arm}/joint_position": obs[f"{leader}/joint_position"]})

Bimanual

bimanual_teleop.py
action = {
    "left_follower/joint_position":  obs["left_leader/joint_position"],
    "right_follower/joint_position": obs["right_leader/joint_position"],
}
obs = robot.step(action)

A policy in the loop

rollout.py
import numpy as np
from c3po import Robot

with Robot(host="10.42.0.1") as robot:
    obs = robot.reset()
    for step in range(600):
        action_vec = policy(obs)                       # your model
        obs = robot.step({"follower/joint_position": action_vec})
        if step % 50 == 0:
            print(robot.spec().effective_control_rate)

Troubleshooting

Symptom Likely cause
RobotNotFoundError Cable unplugged, static IPs not set, or the container isn't running. Check with ping 10.42.0.1, then docker logs -f r2d2-<station>.
reset() times out waiting for observations A camera is declared in the station config but isn't producing frames. The error names the missing keys.
ValueError on step() The action dict doesn't match robot.action_keys. Print it and compare.
RobotDisconnectedError right after stop_recording() Observation streaming has stopped, so use wait_for_status(...) rather than step() while the dataset finalizes.
The loop runs slower than the station rate Your policy is the bottleneck. robot.spec() shows the effective rate.
